# Rxst · Почтовый архив

Просмотр локальных архивов Outlook **PST / OST** на **.NET 10 и Avalonia UI 11.3.22**. Трёхпанельная компоновка в духе Outlook, спокойная тёмная палитра с фиолетовыми акцентами в духе Obsidian. Есть светлая тема.

## Запуск

Готовая сборка для Windows x64: **`artifacts/Rxst-single/Rxst.exe`** — один автономный EXE со встроенными .NET Runtime и библиотеками. Отдельная установка .NET и Microsoft Outlook не требуется.

Из исходников с .NET SDK 10:

```powershell
dotnet build XstReader.slnx -m:1
dotnet run --project src/XstReader.App
# Открыть архив сразу при запуске:
dotnet run --project src/XstReader.App -- "D:\Mail\archive.pst"
```

При запуске показан приветственный экран без демонстрационных писем. Нажмите «Открыть PST или OST» или «Добавить архивы». После закрытия последнего архива приветствие появляется снова. Исходные файлы открываются только для чтения.

## Настройки и язык

Откройте настройки кнопкой ⚙ внизу левой панели или с приветственного экрана. Изменения применяются сразу и автоматически сохраняются между запусками в `%LOCALAPPDATA%\XstReader\settings.json`.

- Русский / English — переключение интерфейса без перезапуска; названия папок и содержимое писем сохраняются в исходном виде.
- Тёмная, светлая или системная тема.
- HTML-просмотр для всех писем. При выключении показывается текст, а ресурсы не загружаются.
- Внешние изображения и CSS: выключены по умолчанию. При включении разрешены HTTP/HTTPS-ресурсы из письма; серверы отправителя могут видеть эти обращения. Скрипты и локальные файлы из HTML не запускаются и не загружаются.
- Встроенные изображения CID/data: отдельный переключатель.
- Размер текста письма: 12–22 px (явные размеры в исходном HTML могут иметь приоритет).
- Автоматический выбор первого письма, поиск по всем архивам после добавления файлов и сортировка по умолчанию.
- Восстановление стандартных настроек.
- Количество сохраняемых запросов: от 0 до 100, по умолчанию 5. Значение 0 отключает историю; при уменьшении лимита остаются самые новые запросы. Лимит сохраняется между запусками.
- Очистка локальной истории поиска. Запросы сохраняются в `settings.search-history.json` рядом с настройками; очистка истории не меняет текст текущего поиска.

Загрузка внешних ресурсов ограничена по времени, числу и размеру файлов и отменяется при смене письма или политики отображения. Вложенные CSS-импорты и CSS-фоновые изображения не загружаются. Для отдельного файла настроек можно задать переменную `XST_SETTINGS_PATH` перед запуском.

## Возможности

- Приложение называется **Rxst**, исполняемый файл — `Rxst.exe`.
- Вложения показаны карточками с двухстрочным названием, описанием формата, размером в байтах / КБ / МБ / ГБ и отдельной кнопкой сохранения. Цветные векторные значки различают таблицы, документы, PDF, презентации, архивы, изображения, аудио, видео, код, почтовые и текстовые файлы.

- Несколько одновременно открытых PST/OST: выберите их вместе в диалоге «Добавить архивы» или добавляйте по очереди. Уже открытый файл повторно не добавляется.
- Каждый архив имеет собственный корень дерева. Пустые служебные папки представлений и поиска скрываются, технические уровни почтового хранилища упрощаются. Путь к выбранной папке раскрывается автоматически. Счётчики в контрастных метках: у архива — сумма по дереву, у папки — непосредственно её содержимое; нули не показываются.
- Закрытие архива: правый клик по имени архива → «Закрыть архив». Файл при этом не удаляется.
- Чтение писем, получателей и свойств MAPI. Сохранение файловых вложений.
- HTML-просмотр с таблицами, цветами, форматированием и встроенными CID-изображениями. Режим «Показать текст без оформления» возвращает текстовую версию. HTML-письма показываются на белом полотне, сохраняя читаемость исходных цветов в обеих темах.
- Поиск в выбранной папке или во всех папках отмеченных архивов по заголовкам: отправителю, получателям, копии и теме. Флажки у корней в боковой панели позволяют включить произвольную группу архивов. «Все» и «Ни одного» меняют выбор сразу; при снятии всех флажков показывается пустая выдача. Активные запрос и фильтры сохраняются при изменении группы. В общей выдаче указан исходный файл.
- При выборе нескольких PST/OST в диалоге открытия их письма сразу объединяются, даже если поиск по всем архивам по умолчанию выключен. Корни сворачиваются для удобного выбора файлов; раскрытие папок доступно отдельно.
- В верхнем поле поиска есть кнопка очистки и кнопка истории запросов (лимит задаётся в настройках, по умолчанию 5). Длинный список прокручивается. Запрос сохраняется по Enter, при уходе из поля или очистке строки; промежуточные символы при наборе не записываются. Выбор из истории применяет запрос и переносит его на первое место. История хранится только на этом устройстве.
- Несколько условий поиска объединяются через И. Поддерживаются фразы в кавычках и операторы `from:`, `to:`, `subject:`. Например: `from:Анна subject:"план проекта"`.
- Совместные фильтры: непрочитанные, вложения, отправитель, начальная и конечная дата включительно.
- Сортировка по дате, отправителю или теме.
- Экспорт выбранного письма в TXT UTF-8 или в его исходный формат HTML / RTF / TXT; экспорт MAPI в CSV.
- Фоновое чтение архивов, кэширование заголовков, защита от отображения результата предыдущего выбора письма.
- `Ctrl+O` — открыть архив; `Ctrl+K` — поиск; `Esc` — сбросить фильтры.

## Архитектура и происхождение

- `src/XstReader.Core` — ядро [Dijji/XstReader](https://github.com/dijji/XstReader), портированное с .NET Framework на .NET 10; исходный commit `3b7856c8b3d01bdf8aa13744e476d1ef7761b832`.
- Сохранены исходные уведомления об авторстве и [MS-PL](../LICENSE). Изменения порта: удаление зависимостей WPF, кроссплатформенный доступ к RTF и признаку прочтения, полное чтение блоков через `ReadExactly`, исправление размера буфера в потоковом RTF-декомпрессоре.
- `src/XstReader.App` — новый интерфейс Avalonia, модель представления, отдельные экземпляры парсера для архивов, сериализованный доступ к чтению, поиск и экспорт.
- Avalonia.HtmlRenderer 11.3.0 используется для HTML-просмотра, HtmlAgilityPack — для подготовки документа и текстового режима, RtfPipe — для чтения RTF без WPF. Скрипты исключаются; внешние изображения и CSS загружаются только по настройке отдельным ограниченным загрузчиком, а HTML-компонент получает подготовленные данные. Ссылки HTTP/HTTPS/mailto открываются во внешнем приложении только при нажатии.
- Новая иконка нарисована из графических примитивов: `tools/draw_icon.py`. Исходные PNG и ICO с размерами 16–256 px находятся в `src/XstReader.App/Assets`; ICO встроен в EXE и используется в заголовке окна.
- Внешний вид вдохновлён [Obsidian](https://obsidian.md); его ресурсы и код не копировались.

## Проверки

```powershell
dotnet run --project tests/XstReader.Checks
# Дополнительно проверить ваши тестовые архивы:
dotnet run --project tests/XstReader.Checks -- "D:\Mail\sample.pst" "D:\Mail\sample.ost"
```

Проверяются составные запросы, кириллица, даты включительно, сортировка, пустая выдача, HTML/RTF, обход папок, отмена чтения, повреждённый файл. При передаче архивов проверяются заголовки, содержимое первых 25 писем, экспорт, доступные вложения и неизменность SHA-256 исходного файла.

Для интеграционной проверки использовались открытые файлы из [java-libpst](https://github.com/rjohnsondev/java-libpst/tree/master/src/test/resources): `example-2013.ost` (3 сообщения), `passworded.pst` (3), `dist-list.pst` (4). Тестовые архивы не входят в готовую сборку. Поиск, фильтр вложений и обе темы дополнительно проверены в работающем окне на Windows.

## Границы текущей версии

Приложение предназначено для просмотра архивов: отправки и синхронизации почты нет. HTML-компонент поддерживает классическую HTML/CSS-вёрстку писем, включая таблицы, но не является полноценным браузером: современные CSS Grid/Flexbox и скрипты не поддерживаются. Внешние изображения и CSS по умолчанию не загружаются. Исходный формат письма можно экспортировать. Поиск выполняется по заголовкам, без индексации тела письма. S/MIME не расшифровывается. Вложенные сообщения и нефайловые вложения отдельно не открываются. Массовый экспорт папок пока отсутствует. Совместимость форматов наследуется от XstReader; проверенные небольшие архивы не заменяют испытания на больших пользовательских базах. На Linux и macOS сборка и интерфейс в этой сессии не проверялись.

## Публикация Windows x64

```powershell
.\tools\publish.ps1
# Или напрямую:
dotnet publish src/XstReader.App -c Release -p:PublishProfile=WindowsSingleFile
```

Профиль `WindowsSingleFile` создаёт `artifacts/Rxst-single/Rxst.exe`: автономный Windows x64 EXE со сжатием, встроенными ресурсами, управляемыми и нативными библиотеками. Обрезка сборок отключена для совместимости с Avalonia и динамическим чтением PST/OST. Скрипт проверяет, что в каталоге публикации находится ровно один EXE.

При первом запуске .NET автоматически распаковывает нативные библиотеки в свой кэш `%TEMP%\.net`; вручную размещать DLL рядом с программой не нужно. Настройки по-прежнему сохраняются отдельно в профиле пользователя. Лицензии встроены в EXE и доступны в «Настройки → О приложении → Лицензии и сторонние компоненты».

Обычный `dotnet build` остаётся сборкой для разработки; файл для распространения создаётся командой публикации выше.
